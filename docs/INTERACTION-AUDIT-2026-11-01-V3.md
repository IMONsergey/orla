# ORLA interaction audit, V3

## Scope and baseline

This pass follows the owner's report that the sites still contain serious interaction, navigation, logo, button and video defects. It does not inherit the previous V2 PASS conclusion.

- Repository baseline: `cd66952ebb37c4a8214f37cdedde8f27657e1dce`.
- Published baseline reviewed by the root agent: `https://orla-imon.vercel.app`.
- Implementation and regression environment: the local production build, served on loopback with HTTP Range support. Nothing in this pass was committed, pushed or deployed.
- Test fixtures intercept enquiry requests inside the browser. The preview rejects POST. No enquiry was sent to the production endpoint or to a person.
- Source scope: all controls in `index.astro`, `Enquiry.astro`, `main.ts` and `media-interactions.ts`. The rendered inventory contains 113 control/form/media entries. An entry is an inventory item, not an individual claim of runtime coverage.

## Logo and media provenance

The source Figma file is `m3N3lJCoutaziEm4nt4CwO`. Footer group 1:325 contains the ORLA layer 1:331 and Dorchester layer 1:330. Their returned node renders establish horizontal wordmark frames; the returned raw fill images were square and could not be used as natural-ratio logos. Node PNG renders also include an opaque navy backdrop. They were useful references but were rejected as final assets because the backdrop makes visible rectangles over the footer photograph.

`BrandWordmark.astro` instead crops the existing transparent white original from source node 1:1668, asset `imgOrlaDcDubaiFullWhite2`. The original 2880×2880 raster is unchanged. Its alpha bounds are ORLA `(973,876)-(2174,1164)` and Dorchester `(625,1461)-(2522,1671)`. The component computes a uniform scale and clip position from these bounds and the footer reference frames. This retains letter proportions and transparency. Header group 1:345 already uses its 213×98 and 213×52 source canvases correctly; its authored geometry is retained. The partner logo in 1:301 uses the existing 315×44 authored slot; the mobile menu restores the corresponding 213×98 ORLA canvas.

The preview is the existing `public/media/orla-film-preview.mp4`. The new poster was extracted with `ffmpeg -ss 1 -i ... -frames:v 1 -q:v 2`; no crop, scale or content generation was applied.

## Verification and limits

The compact machine-readable results and selected screenshots are in `docs/verification/interaction-v3/`. The initial failed local WebKit media attempt used Python's simple HTTP server, which returned no video byte ranges. On the corrected preview,206/Content-Range responses restored WebKit playback. This was a fixture problem, not a production-code workaround. Early partner screenshots taken before lazy image decode were likewise rejected as final proof.

The final main suite covers Chromium 1440×900, Chromium touch 390×844 and WebKit touch 390×844. It reported 32 groups; three preliminary logo geometry groups were superseded after visual review, leaving 29 behavioral groups in the compact final report. The existing motion harness passed its six focused hero/film/hotspot checks in Chromium and WebKit. Its former “Watch must not autoplay” assertion was changed to the actual single-click Watch contract; its pointer/focus/scroll checks were retained. The final feature/logo probe passed four groups covering failure/Retry, latest intent, Close and the final decoded desktop/mobile logos. The final color check passed all six computed foreground/background pairs. TypeScript, the production build, the existing enquiry test module and `git diff --check` also passed.

These checks establish the named behavior and rendered states. They do not establish 60 fps on every device, eliminate all possible network failures, validate current property availability, or verify production delivery of a real enquiry. No full-length promotional film or PDF was fabricated. The previous V2 report remains untouched.
