# ORLA media and dialog verification

The current interaction patch adds `src/scripts/media-interactions.ts` and connects it from `main.ts`. The enquiry/API block is unchanged. The root task owns the scroll narratives, source composition and page.css.

## Gallery

- With normal motion, click Next/Previous and use keyboard arrows. The requested source image must decode before a 650 ms horizontal wipe. Next enters from the right and Previous from the left. The outgoing image remains fully opaque underneath, preventing a navy/blank flash between photographs.
- Delay the next image request and issue several forward/back commands. Only the latest request may take effect. The counter and active image must agree; Enlarge opens the image actually selected for display, never a still-pending target. Failed decode keeps the existing frame.
- Horizontal swipe works only in the photograph region, not the copy below it on mobile. Vertical swipe continues the page; pointer cancellation and lost capture clear the gesture. A following intentional button click must work immediately, without opening the viewer accidentally after a swipe.
- Change reduced motion during a transition. The current decoded frame settles immediately; subsequent switches do not animate.

## Zoom and source plan crop

- Enlarge both a gallery photograph and Residence 401 from its nested details dialog. Loading must not display the previously viewed image. A source image failure shows an explicit loading-error message and can be retried by closing/reopening.
- The plan remains the same cropped brochure-page canvas. `.zoom-canvas.is-plan` keeps its aspect ratio, percentage image size/offsets and the leading `translate(-50%,-50%)`. No full-page plan replacement or source crop rewrite is made.
- On a short/landscape viewport, Fit also scales the existing crop canvas to fit the available stage. On normal viewports its original base size is retained. Zoom/pan bounds use the crop canvas for plans, and the actual fitted image box for photographs.
- Pinch, release one pointer and continue panning. There must be no jump. Repeat after pointercancel/lostcapture, resize and close/reopen. Wheel zoom is anchored at the pointer; Fit and keyboard controls remain usable and zoom-limit buttons disable.

## Dialogs and Safari

- Open/close Menu, Feature, Residence, Presentation and Enquiry from actual buttons. Escape must return focus to the initiating visible control, including Safari where clicking a button does not reliably focus it.
- Open Residence -> Plan, then close only Plan. The residence remains open and focus returns to its plan trigger. Repeat Feature -> Enquiry and Menu -> Enquiry, returning through each layer. Root scroll remains locked until the last dialog closes.
- Opening/closing dialogs must not move page content horizontally. Small centered dialogs retain their original translate(-50%,-50%) positioning; entrance animation changes only opacity.
